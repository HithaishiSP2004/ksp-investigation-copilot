## 1. Authentication

### Type
**Zoho Catalyst Authentication** — Email / Organization login via Catalyst Auth SDK.

The application integrates the Catalyst Web Client SDK loaded via the `<Script>` tag in the root layout. It detects the `window.catalyst.auth` instance at runtime and calls `getCurrentUser()` to restore the officer session.

In local development (when `NEXT_PUBLIC_CATALYST_PROJECT_ID` is absent or set to `mock_project_id`), the application automatically falls back to **mock KGID/password authentication** stored in `localStorage`.

### Required Test Users

| KGID | Name | Role | Password |
|---|---|---|---|
| `123456` | Ramesh Kumar | Sub-Inspector (Investigating Officer) | `password` |
| `999999` | Kiran Reddy | DSP (Supervisor) | `password` |

### Redirect & Callback URLs

Configure these inside the **Catalyst Authentication** service settings:

| Setting | Value |
|---|---|
| **Login Redirect URL** | `https://<your-app>.catalystserverless.in/` |
| **Logout Redirect URL** | `https://<your-app>.catalystserverless.in/` |
| **Allowed Origins (CORS)** | `https://<your-app>.catalystserverless.in` |

### Login Flow
1. Officer opens the hosted URL.
2. The Catalyst SDK checks for an active session cookie.
3. If no session exists, the application renders the KGID + Password login form.
4. On successful credential validation, the officer session is persisted and the Dashboard is rendered.
5. Officers with KGID `999999` get the `supervisor` role; all others receive the `investigator` role.

## 3. File Store

All forensic evidence file uploads are stored in Catalyst File Store.

| Folder | Purpose | Accepted File Types | Permissions |
|---|---|---|---|
| `/evidence/documents/` | FIR-related PDFs, text files, scanned forms | `.pdf`, `.txt`, `.docx` | Authenticated officers: read/write |
| `/evidence/images/` | CCTV screenshots, scene photographs | `.jpg`, `.jpeg`, `.png`, `.webp` | Authenticated officers: read/write |
| `/evidence/videos/` | Surveillance recordings, interview clips | `.mp4`, `.mov`, `.avi` | Authenticated officers: read/write |
| `/evidence/audio/` | Intercepted call recordings, dictation | `.mp3`, `.wav`, `.ogg` | Authenticated officers: read/write |
| `/evidence/devices/` | Metadata exports from digital devices | `.json`, `.csv`, `.xml` | Authenticated officers: read/write |

**Max File Size**: 25MB per upload (Catalyst Free Tier; raise on paid plan).  
**Naming Convention**: Files are stored using `evidenceNo` + original extension (e.g., `EV-2026-000123.pdf`).

## 4. Functions

The current release uses **no Catalyst Functions**. All business logic runs client-side. The following functions are required when migrating to live Catalyst Data Store and Zia OCR:

| Function Name | Runtime | Trigger | Purpose |
|---|---|---|---|
| `ocr-extract` | Node.js 18 | HTTP (Evidence upload) | Calls Catalyst Zia OCR API on uploaded evidence files and writes results to `IntelligenceRecord` table |
| `entity-extract` | Node.js 18 | HTTP (Post-OCR) | Runs entity extraction over OCR text via Zia NLP and populates `ExtractedEntity` records |
| `report-compile` | Node.js 18 | HTTP (On demand) | Compiles a structured report JSON from Data Store records for a given `caseId` |

> **Note**: These functions are NOT deployed in the current release. The application uses mock provider implementations that simulate these operations client-side.

## 8. Deployment Order

Follow this exact sequence when setting up a new Catalyst project:

1. **Create Catalyst Project** via the [Catalyst Console](https://catalyst.zoho.com)  
   → Project Name: `KSP_Investigation_Copilot`

2. **Enable Authentication**  
   → Configure login redirect URLs  
   → Create the test officer accounts listed in Section 1

3. **Create Data Store Tables**  
   → Create all tables from Section 2 in the exact column order listed  
   → Seed all Lookup Tables (CaseCategory, GravityOffence, CrimeHead, CrimeSubHead, Unit, Employee) with the reference values from `case-repository.ts`

4. **Configure File Store**  
   → Create folders listed in Section 3  
   → Set read/write permissions for authenticated users

5. **Set Environment Variables**  
   → In Catalyst Console → Project Settings → Environment Variables  
   → Add all variables from Section 6

6. **Build the Application**  
   ```bash
   npm install
   npm run build
   ```
   → Verify the `out/` folder is generated

7. **Update `catalyst.json`**  
   → Populate the `"id"` field with the actual Catalyst project ID:
   ```json
   {
     "project": {
       "name": "KSP_Investigation_Copilot",
       "id": "YOUR_PROJECT_ID"
     },
     "client": {
       "source": "out"
     }
   }
   ```

8. **Deploy to Catalyst**  
   ```bash
   catalyst login
   catalyst use
   catalyst deploy
   ```

9. **Verify Deployment**  
   → Open the URL from `catalyst deploy` output  
   → Complete the Post-Deployment Verification checklist below
